Section 01

The Big Picture — What We're Building

Before touching a single line of code, let's get crystal clear on what a working MCP server looks like end-to-end and how our code fits into the system we studied in Part 1.

An MCP Server is just a program that listens for JSON-RPC messages, executes code when asked, and sends back results. It's surprisingly simple once you see the pattern.

Diagram 2.1 — Complete Flow: Claude Desktop → Our Server → Response
The complete request-response cycle. User asks → Claude decides to call our tool → JSON-RPC over stdin → our server executes Python code → result back over stdout → Claude replies to user.
🧠 Mental Model Before We Code

Your MCP Server is just a Python process that reads JSON from stdin and writes JSON to stdout. FastMCP handles all the protocol details — you just write normal Python functions and decorate them with @mcp.tool(). That's it. No asyncio boilerplate, no manual JSON Schema, no routing logic.

The Server Skeleton

Python — main.py (skeleton)

# ─────────────────────────────────────────────────────────────

# ─────────────────────────────────────────────────────────────
# ENTRY POINT — mcp.run() does everything:
# starts asyncio, connects stdio transport, handles init.
# No async def main(), no asyncio.run() needed.
# ─────────────────────────────────────────────────────────────

    mcp.run()

Does FastMCP still use async?

Yes — FastMCP uses asyncio internally, but it hides all of it from you. You can write your tool functions as plain synchronous def (FastMCP runs them in a thread pool), or as async def if you need to do async I/O like network calls. Either works — FastMCP adapts automatically. You never write asyncio.run() or manage event loops yourself.

Diagram 2.2 — How asyncio Handles Multiple MCP Requests
asyncio lets the server handle multiple requests concurrently. While waiting for one async operation (e.g. network call), it processes other requests. No request blocks another.

Section 04

Building Your First Two Tools

Now we add real capabilities. In MCP Python SDK, you register a tool by adding a handler for the list_tools request (which tells Claude what tools exist) and for the call_tool request (which executes them). Let's build both tools step by step.

How Tool Registration Works in FastMCP

With the raw MCP SDK you needed two separate handlers: one to list tools (list_tools) and one to execute them (call_tool). FastMCP collapses both into a single decorator:

  • @mcp.tool() — Decorate any function and it becomes an MCP tool. FastMCP automatically generates the tool name (from the function name), description (from the docstring), and input schema (from Python type annotations). No manual JSON Schema needed.
🔑 FastMCP reads your Python types

A parameter typed as city: str becomes {"type": "string"} in the JSON Schema automatically. weight_kg: float becomes {"type": "number"}. include_forecast: bool = False becomes an optional boolean with a default. FastMCP handles all of this — you just write normal Python function signatures.

Diagram 2.3 — Tool Registration vs Tool Execution Flow
In FastMCP, @mcp.tool() replaces both phases. FastMCP handles discovery (list_tools) and routing (call_tool) automatically. You write one function; FastMCP exposes it as a full MCP tool.

Tool 1 — get_weather

Add this to main.py after creating the mcp object. One decorator is all you need — FastMCP reads the function name, docstring, and type hints automatically.

Python — list_tools handler (tells Claude what tools exist)
@mcp.tool()
def get_weather(city: str) -> str:
    """
    Get the current weather for a city.                     # LLM reads THIS!
    Returns temperature, conditions, and humidity.           # be precise & clear
    Use this when the user asks about weather,
    temperature, or whether to bring an umbrella.
    """
    # FastMCP guarantees `city` is a str — no manual arg extraction
    mock_data = {
        "Mumbai":   {"temp": 34, "condition": "Partly Cloudy", "humidity": 78},
        "Delhi":    {"temp": 42, "condition": "Sunny",         "humidity": 30},
        "London":   {"temp": 14, "condition": "Rainy",          "humidity": 85},
        "New York": {"temp": 22, "condition": "Clear",          "humidity": 55},
    }
    weather = mock_data.get(city.title(), {"temp": 25, "condition": "Unknown", "humidity": 60})

    # Return a plain string — FastMCP wraps it in TextContent automatically
    return f"""🌤️ Weather for {city.title()}:
   Temperature : {weather['temp']}°C
   Condition   : {weather['condition']}
   Humidity    : {weather['humidity']}%"""


@mcp.tool()
def calculate_bmi(weight_kg: float, height_cm: float) -> str:
    """
    Calculate Body Mass Index (BMI) from weight and height.
    Returns BMI value, category (Underweight/Normal/Overweight/Obese),
    and basic health advice. Use when user mentions weight and height.
    """
    if weight_kg <= 0 or height_cm <= 0:
        return "❌ Weight and height must be positive numbers."

    bmi = round(weight_kg / (height_cm / 100) ** 2, 1)

    if   bmi < 18.5: category, advice = "Underweight", "Consider consulting a nutritionist."
    elif bmi < 25.0: category, advice = "Normal weight", "You're in a healthy range! ✓"
    elif bmi < 30.0: category, advice = "Overweight",    "Diet and exercise improvements may help."
    else:            category, advice = "Obese",          "Please consult a healthcare professional."

    return f"""⚖️  BMI Calculation:
   Weight     : {weight_kg} kg
   Height     : {height_cm} cm
   BMI Score  : {bmi}
   Category   : {category}
   Advice     : {advice}"""
⚠️ The Most Important Part: Tool Docstrings

The function docstring is what the LLM reads to decide when to call your tool. In FastMCP there is no separate description field — the docstring IS the description. Write it like you're explaining the tool to a smart person who has never seen it. Include: what it does, what data it returns, and when to use it. Bad docstrings = tool never gets called or gets called at wrong times.

What FastMCP returns to Claude

In the raw SDK, tools must return a list[TextContent] with explicit type fields. FastMCP removes this boilerplate — just return a plain string, dict, or Pydantic model and FastMCP wraps it correctly. For advanced use you can still return typed content objects directly.

Return valueFastMCP sends to Claude
return "some text"TextContent(type="text", text="some text")
return {"key": "val"}JSON-serialised TextContent automatically
return Image(...)ImageContent — for charts, screenshots
Section 05

Input Schema Validation

When Claude calls your tool with arguments, how do you ensure those arguments are valid? What if Claude sends a string where you expect a number? What if a required field is missing? This is where JSON Schema and Pydantic come in.

Layer 1 — JSON Schema (auto-generated by FastMCP)

FastMCP automatically converts your function signature to a JSON Schema. This schema does two things simultaneously:

  1. Guides the LLM — Claude reads the schema to know what arguments to provide when calling the tool. Your Python type hints directly influence what Claude sends.
  2. Documents the API — MCP Inspector and other tooling use the schema to build UI and catch bad calls before they reach your code.

Understanding what FastMCP generates helps you write better type hints:

JSON Schema is a standard for describing the shape of JSON data. Here's how every key part works:

JSON Schema — Complete Field Guide
{
  "type": "object",          // Top-level is always "object" (a dict of args)

  "properties": {            // Define each argument here
    "city": {
      "type": "string",       // Valid types: string, number, integer, boolean, array, object
      "description": "...", // LLM reads this — make it informative!
      "minLength": 1,          // Optional: string must be non-empty
      "maxLength": 100         // Optional: string max length
    },
    "weight_kg": {
      "type": "number",       // Accepts floats (70.5 is valid)
      "minimum": 1,           // Optional: value must be ≥ 1
      "maximum": 500          // Optional: value must be ≤ 500
    },
    "age": {
      "type": "integer",      // Only whole numbers (no 25.5)
    },
    "unit": {
      "type": "string",
      "enum": ["metric", "imperial"]  // Only these exact values allowed
    },
    "include_forecast": {
      "type": "boolean",      // true or false only
      "default": false        // Used if not provided
    }
  },

  "required": ["city", "weight_kg"],  // THESE fields MUST be provided
  "additionalProperties": false           // Reject any extra unknown fields
}

Layer 2 — Pydantic (Python-level validation)

JSON Schema validates the shape, but you should also validate the values inside your Python code using Pydantic. Pydantic lets you define a Python class that describes your expected arguments — it automatically validates, converts types, and raises helpful errors.

Python — Pydantic models for argument validation
from pydantic import BaseModel, Field, validator

# Define a Pydantic model for each tool's arguments
class WeatherArgs(BaseModel):
    city: str = Field(
        ...,                              # ... means required (no default)
        min_length=1,
        max_length=100,
        description="City name for weather lookup"
    )

    # Custom validator — runs after type check
    @validator("city")
    def city_must_be_non_empty(cls, v):
        if not v.strip():
            raise ValueError("City cannot be whitespace only")
        return v.strip().title()   # normalize: "MUMBAI" → "Mumbai"


class BmiArgs(BaseModel):
    weight_kg: float = Field(..., gt=0, le=500)   # gt=greater than 0
    height_cm: float = Field(..., gt=0, le=300)   # le=less than or equal 300


# --- Using the models in your tool handler ---
async def _get_weather(arguments: dict):
    try:
        args = WeatherArgs(**arguments)   # validates AND converts types
    except Exception as e:
        raise types.McpError(
            types.ErrorCode.INVALID_PARAMS,
            f"Invalid arguments: {e}"
        )

    city = args.city   # guaranteed to be a clean, capitalized string
    # ... rest of your logic
🔑 Two-Layer Validation Strategy

In FastMCP: Python type annotations → JSON Schema automatically (FastMCP generates it). Pydantic → pass a BaseModel as a function argument and FastMCP validates it before your function even runs. You never touch a raw arguments dict.

Section 06

Exposing Resources

Resources let the AI read data passively — like attaching a file to a conversation. Unlike tools, resources have no side effects and are identified by URIs (addresses). We'll build two: one static (always the same content) and one dynamic (content changes based on the URI).

How Resources Work in MCP

In FastMCP, resources use a single decorator just like tools — no separate list/read handlers needed:

  • @mcp.resource("resource://path") — For static resources with a fixed URI. FastMCP lists and reads it automatically.
  • @mcp.resource("resource://path/{param}") — For dynamic resources with URI template parameters. FastMCP extracts the parameter from the URI and passes it as a function argument.
Diagram 2.4 — Static vs Dynamic Resource URI Patterns
Static resources have a fixed URI. Dynamic resources use URI templates with {variable} slots — the same handler serves many different URIs based on what's in the {slot}.

Implementing Both Resource Types

Python — @mcp.resource() decorators (static and dynamic)
# ─── STATIC RESOURCE — same content every time ───────────────
HEALTH_TIPS = """# Daily Health Tips
1. 💧 Drink 8 glasses of water daily
2. 😴 Sleep 7-9 hours per night
3. 🏃 Exercise at least 30 min/day
4. 🥦 Eat 5 portions of fruit/veg daily
5. 🚫 Limit processed foods and sugar
"""

@mcp.resource("resource://health/tips")       # fixed URI — no parameters
def health_tips() -> str:
    """Daily health and wellness tips document."""
    return HEALTH_TIPS                           # plain string — FastMCP wraps it


# ─── DYNAMIC RESOURCE — URI Template with {city} slot ────────
@mcp.resource("resource://weather/{city}")    # {city} becomes a function arg
def city_weather(city: str) -> str:
    """Weather data for a specific city. Replace {city} with city name."""
    mock_data = {
        "mumbai": {"temp": 34, "condition": "Partly Cloudy", "humidity": 78},
        "london": {"temp": 14, "condition": "Rainy",          "humidity": 85},
    }
    # FastMCP extracts city from the URI and passes it directly as an arg
    w = mock_data.get(city.lower(), {"temp": 25, "condition": "Unknown", "humidity": 60})
    return f"Weather for {city.title()}: {w['temp']}°C, {w['condition']}, {w['humidity']}% humidity"

MIME Types — Tell the Client What Format the Data Is

The mimeType field tells the MCP Client what type of content you're returning. This matters because the Host can render it differently depending on the type:

mimeTypeUse for
text/plainPlain text, log output, free-form strings
application/jsonStructured data — config files, API responses
text/markdownMarkdown documents — README files, docs
image/png or image/jpegBinary image data (use BlobResourceContents)
Section 07

Error Handling

Your server will encounter bad input, missing data, network failures, and edge cases. Handling these gracefully is essential — a crashed server is useless, and a server that returns cryptic errors confuses both the LLM and the user.

The Two Types of Errors in MCP

MCP distinguishes between two fundamentally different kinds of errors, and you must handle them differently:

🔴 Protocol Errors

Something went wrong at the MCP layer — unknown tool name, missing required parameter, invalid JSON. Raise a Python exception (ValueError, TypeError, etc). FastMCP converts it to a JSON-RPC error automatically.

🟡 Tool Execution Errors

Your tool ran successfully, but the result is an error (e.g. city not found, API down). Return the error as a plain string from your tool function. The LLM reads it and explains the problem to the user intelligently.

⚠️ Critical Distinction

This confuses many beginners. A "city not found" error is not a protocol error — your code ran fine, it just found no data. Return it as a string from the function. Only raise a Python exception for things like wrong argument types or logic errors — FastMCP handles the rest.

Python — Error Handling in FastMCP
# ── PATTERN 1: Return error string (business logic failure) ───
# Tool functions just return strings — error messages are strings too
@mcp.tool()
def get_weather(city: str) -> str:
    """Get current weather for a city."""
    if not city.strip():
        # ✓ Return a friendly error string — no exception needed
        return "❌ City name cannot be empty."

    try:
        weather_data = fetch_weather_api(city)
    except CityNotFoundError:
        return f"❌ City '{city}' not found. Try: Mumbai, Delhi, London."
    except APITimeoutError:
        return "❌ Weather API timed out. Please try again in a moment."
    except Exception as e:
        return f"❌ Unexpected error: {str(e)[:200]}"
    return format_weather(weather_data)


# ── PATTERN 2: Raise exception (invalid input — protocol error) ─
# FastMCP converts Python exceptions → MCP error codes automatically
@mcp.tool()
def calculate_bmi(weight_kg: float, height_cm: float) -> str:
    """Calculate BMI from weight and height."""
    if weight_kg <= 0 or height_cm <= 0:
        raise ValueError("weight_kg and height_cm must be positive")
        # FastMCP → McpError(INVALID_PARAMS) automatically
    # ... rest of logic


# ── FASTMCP EXCEPTION → MCP ERROR CODE MAPPING ───────────────
# ValueError, TypeError   → INVALID_PARAMS   (-32602)
# NotImplementedError     → METHOD_NOT_FOUND  (-32601)
# PermissionError         → INTERNAL_ERROR    (-32603)
# Any other Exception     → INTERNAL_ERROR    (-32603)
#
# You never need to import McpError or ErrorCode directly —
# FastMCP handles the mapping from standard Python exceptions.

The Golden Rule of MCP Error Handling

✅ Rule: Never crash. Always respond.

Wrap all tool logic in try/except. In FastMCP, unhandled exceptions are caught and converted to error responses automatically — but you should still handle specific errors yourself so you can return helpful messages. Always prefer returning a clear error string over crashing.

5. 🚫 Limit processed foods and sugar
6. 🧘 Practice mindfulness or meditation
7. ☀️ Get 15-20 min of sunlight daily

MOCK_WEATHER = {

   Weight   : {weight_kg} kg
   Height   : {height_cm} cm
   BMI      : {bmi}

   Advice   : {adv}"""
