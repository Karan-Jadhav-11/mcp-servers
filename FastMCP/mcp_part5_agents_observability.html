Section 01

What is an AI Agent?

Before we build one, we need a precise definition. The word "agent" is overused in AI. Here's what it means in the MCP context:

An AI Agent is a system where an LLM autonomously decides what actions to take, executes them using tools, observes the results, and repeats — until it reaches a goal the user specified in natural language — without human intervention between steps.

// DEFINITION: AI AGENT IN MCP

The Three Properties That Make Something an Agent

🎯 Goal-Directed

The system is given a high-level goal ("Research the top 5 AI companies") and figures out the intermediate steps itself — it's not told exactly what to do.

🔄 Multi-Step Loop

The system can take multiple sequential actions, observe results, and decide what to do next based on what it learned — not just a single call-and-return.

🧠 Autonomous Decision-Making

The LLM decides autonomously which tools to call and in what order. There's no human choosing "now call search, now call summarize."

The Difference: Tool Use vs. Agent

ConceptTool Use (Parts 1–4)Agent (Part 5)
StepsSingle: user asks → tool called → result returnedMulti: loop runs until goal is achieved
Decision-makerLLM picks one tool per turnLLM plans a whole sequence of tools
MemoryOnly the current conversationPersistent across turns via Memory resources
AutonomyHuman approves each stepAgent runs independently (with optional gates)
Complexity"What's the weather in Mumbai?""Write a research report on AI trends in healthcare"
Section 02

The ReAct Loop

ReAct (Reasoning + Acting) is the dominant pattern for building AI agents. It was introduced in a 2022 research paper and has since become the foundation of almost every production agent system. The pattern is elegantly simple:

Diagram 5.1 — The ReAct Loop: Reason → Act → Observe → Repeat
Each loop iteration: LLM reasons about what to do next, calls a tool (Act), receives the result (Observe), then reasons again. Loops until the LLM judges the goal is achieved.

ReAct in Code — The Core Loop

Python — ReAct agent loop using Anthropic API + fastmcp.Client
import anthropic, json
from fastmcp import Client

ANTHROPIC = anthropic.Anthropic()

class ReActAgent:
    """
    Implements the ReAct loop:
      1. Send conversation history + available tools to LLM
      2. LLM either: (a) calls a tool, or (b) returns final answer
      3. If (a): execute tool via MCP, add result to history, go to 1
      4. If (b): return final answer to user
    """

    def __init__(self, client: Client, system_prompt: str, max_iterations: int = 15):
        self.client          = client
        self.system_prompt  = system_prompt
        self.max_iterations = max_iterations
        self.history        = []   # full conversation history

    async def run(self, goal: str) -> str:
        """Execute the ReAct loop until goal is achieved or max_iterations hit."""

        # Get available tools from MCP server — fastmcp.Client returns
        # the tool list directly, no .tools wrapper needed
        tools = await self.client.list_tools()
        tools_for_llm = [
            {
                "name":        t.name,
                "description": t.description,
                "input_schema": t.inputSchema,
            }
            for t in tools
        ]

        # Seed the conversation with the user's goal
        self.history = [{"role": "user", "content": goal}]

        for iteration in range(self.max_iterations):
            print(f"\n{'─'*50}")
            print(f"🔄 Iteration {iteration + 1}/{self.max_iterations}")

            # ── REASON: Ask LLM what to do next ──────────────────────
            response = ANTHROPIC.messages.create(
                model="claude-opus-4-5",
                max_tokens=4096,
                system=self.system_prompt,
                tools=tools_for_llm,
                messages=self.history,
            )

            # Append LLM response to history
            self.history.append({"role": "assistant", "content": response.content})

            # ── CHECK: Did the LLM finish? ────────────────────────────
            if response.stop_reason == "end_turn":
                # LLM decided it's done — extract final text response
                final_text = "".join(
                    block.text for block in response.content
                    if hasattr(block, "text")
                )
                print(f"✅ Goal achieved in {iteration + 1} iterations")
                return final_text

            # ── ACT: Execute all tool calls the LLM requested ────────
            tool_results = []
            for block in response.content:
                if block.type != "tool_use":
                    continue

                print(f"  ⚡ Calling: {block.name}({json.dumps(block.input)[:80]})")

                # Execute via MCP ← the key connection between agent + MCP
                mcp_result = await self.client.call_tool(block.name, block.input)

                # .data is the unwrapped return value of your tool function
                result_text = str(mcp_result.data) if mcp_result.data is not None else ""
                print(f"  👁️ Observed: {result_text[:120]}...")

                tool_results.append({
                    "type":        "tool_result",
                    "tool_use_id": block.id,
                    "content":     result_text,
                })

            # ── OBSERVE: Add all tool results to history ──────────────
            self.history.append({"role": "user", "content": tool_results})

        return "⚠️ Max iterations reached without completing the goal."

Section 03

Agent Memory via MCP Resources

By default, an agent forgets everything when the conversation ends. For a truly useful agent, you need persistence — the ability to remember past tasks, learn user preferences, and build on previous work across sessions.

MCP Resources are the perfect mechanism for agent memory: the agent reads memory resources at the start of each task and writes updated memory back through tools at the end.

Diagram 5.2 — Three Layers of Agent Memory via MCP
Three memory tiers: Working (current task), Episodic (past tasks), Semantic (permanent knowledge). Each is a separate MCP Resource URI. The agent reads before acting and writes after completing.
Python — FastMCP agent memory server (all three memory tiers)
import json, aiosqlite
from fastmcp import FastMCP

mcp = FastMCP("agent-memory-server")

# ── Working memory: in-process dict (fast, ephemeral) ────────
_working_memory: dict[str, dict] = {}   # session_id → data

# ── Episodic memory: SQLite (persists to disk) ───────────────
MEMORY_DB = "agent_memory.db"

async def init_db():
    async with aiosqlite.connect(MEMORY_DB) as db:
        await db.execute("""
            CREATE TABLE IF NOT EXISTS episodes (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                ts TEXT, goal TEXT, summary TEXT,
                outcome TEXT, tools_used TEXT, duration_secs REAL
            )""")
        await db.execute("""
            CREATE TABLE IF NOT EXISTS knowledge (
                topic TEXT PRIMARY KEY,
                content TEXT, updated_at TEXT
            )""")
        await db.commit()

# ── RESOURCES: each memory tier gets its own @mcp.resource() —
# FastMCP routes by URI automatically, no manual if/startswith chain ─

@mcp.resource("resource://memory/session/{session_id}")
async def working_memory(session_id: str) -> str:
    """Working memory for the current agent session."""
    data = _working_memory.get(session_id, {})
    return json.dumps(data, indent=2)


@mcp.resource("resource://memory/episodes")
async def episodic_memory() -> str:
    """Recent episodic memories — the last 10 completed tasks."""
    async with aiosqlite.connect(MEMORY_DB) as db:
        db.row_factory = aiosqlite.Row
        async with db.execute(
            "SELECT * FROM episodes ORDER BY ts DESC LIMIT 10"
        ) as cur:
            rows = [dict(r) async for r in cur]
    return json.dumps(rows, indent=2)


@mcp.resource("resource://memory/knowledge/{topic}")
async def semantic_memory(topic: str) -> str:
    """Permanent knowledge stored on a given topic."""
    async with aiosqlite.connect(MEMORY_DB) as db:
        async with db.execute(
            "SELECT content FROM knowledge WHERE topic=?", (topic,)
        ) as cur:
            row = await cur.fetchone()
    return row[0] if row else f"No knowledge stored for topic: {topic}"
    # Unknown URIs (e.g. a typo'd topic that 404s upstream) are handled
    # by FastMCP automatically — no manual McpError/RESOURCE_NOT_FOUND needed


# ── TOOLS: write to memory — typed params replace manual JSON Schema ──

@mcp.tool()
def remember_working(session_id: str, key: str, value: str) -> str:
    """Store a key-value pair in working memory for the current session."""
    _working_memory.setdefault(session_id, {})[key] = value
    return f"✓ Remembered '{key}' for session {session_id}"


@mcp.tool()
async def save_episode(goal: str, summary: str, outcome: str, tools_used: str = "") -> str:
    """
    Save a completed task to episodic memory for future reference.
    outcome must be one of: success, partial, failed.
    """
    if outcome not in ("success", "partial", "failed"):
        return f"❌ outcome must be success/partial/failed, got '{outcome}'"
    async with aiosqlite.connect(MEMORY_DB) as db:
        await db.execute(
            "INSERT INTO episodes (ts, goal, summary, outcome, tools_used) "
            "VALUES (datetime('now'), ?, ?, ?, ?)",
            (goal, summary, outcome, tools_used)
        )
        await db.commit()
    return f"✓ Episode saved: {goal[:60]}... [{outcome}]"


@mcp.tool()
async def store_knowledge(topic: str, content: str) -> str:
    """Store a permanent fact or preference in semantic memory."""
    async with aiosqlite.connect(MEMORY_DB) as db:
        await db.execute(
            "INSERT INTO knowledge (topic, content, updated_at) VALUES (?, ?, datetime('now')) "
            "ON CONFLICT(topic) DO UPDATE SET content=excluded.content, updated_at=excluded.updated_at",
            (topic, content)
        )
        await db.commit()
    return f"✓ Knowledge stored for topic '{topic}'"

if __name__ == "__main__":
    import asyncio
    asyncio.run(init_db())   # ensure tables exist before serving
    mcp.run()

Multi-Agent Systems

Complex tasks often benefit from specialization. A research task has sub-tasks: web searching, data summarizing, writing — each suited to a different specialist. Multi-agent systems assign sub-tasks to specialist agents and coordinate their outputs.

Diagram 5.3 — Multi-Agent System: Orchestrator + Specialist Sub-Agents
The Orchestrator decomposes a complex goal, delegates each sub-task to a specialist agent with the right tools, then merges their outputs into a final coherent result.
Python — Orchestrator spawning and delegating to sub-agents
class OrchestratorAgent:
    """
    High-level agent that:
    1. Decomposes a complex goal into sub-tasks
    2. Assigns each to a specialist ReActAgent
    3. Merges all results into a final answer
    """

    def __init__(self, specialist_clients: dict[str, Client]):
        self.specialists = {
            name: ReActAgent(
                client=client,
                system_prompt=SPECIALIST_PROMPTS[name],
                max_iterations=8
            )
            for name, client in specialist_clients.items()
        }

    async def run(self, goal: str) -> str:
        print(f"🎯 Orchestrating goal: {goal[:80]}...")

        # Step 1: Decompose goal into sub-tasks using LLM planning
        plan = await self._plan(goal)
        print(f"📋 Plan: {len(plan)} sub-tasks identified")

        # Step 2: Execute sub-tasks (in parallel where possible)
        results = {}
        # Run researcher and analyst simultaneously — they're independent
        research_task  = self.specialists["researcher"].run(plan["research"])
        analytics_task = self.specialists["analyst"].run(plan["analysis"])
        results["research"], results["analysis"] = \
            await asyncio.gather(research_task, analytics_task)

        # Writer depends on researcher + analyst output, so runs after
        writer_context = f"""
Research findings: {results['research'][:2000]}
Analysis results:  {results['analysis'][:2000]}
Writing task: {plan['writing']}
"""
        results["writing"] = await self.specialists["writer"].run(writer_context)

        # Step 3: Final synthesis
        return await self._synthesize(goal, results)

    async def _plan(self, goal: str) -> dict:
        """Use LLM to decompose goal into specialist sub-tasks."""
        resp = ANTHROPIC.messages.create(
            model="claude-opus-4-5", max_tokens=1024,
            messages=[{"role":"user", "content":f"""
Decompose this goal into three specialist sub-tasks.
Goal: {goal}
Return JSON: {{"research": "...", "analysis": "...", "writing": "..."}}
JSON only, no other text."""}]
        )
        return json.loads(resp.content[0].text)

Human-in-the-Loop Approval

Autonomous agents are powerful — and dangerous when they make mistakes. For destructive or irreversible actions (delete, send, deploy, charge), always pause and ask the human before proceeding. This is called a human-in-the-loop gate.

⚠️ The Rule: Asymmetric Autonomy

Let agents run fully autonomously for read operations (search, query, analyze). Require human approval for write operations (send email, delete file, deploy, charge card, post to social media). A mistake in a read is recoverable. A sent email or deleted file is not.

Python — Human-in-the-loop approval gate in MCP server
import asyncio
from enum import Enum

class RiskLevel(Enum):
    LOW      = "low"       # read-only: auto-approve
    MEDIUM   = "medium"    # write, reversible: warn but allow
    HIGH     = "high"      # destructive/irreversible: REQUIRE approval
    CRITICAL = "critical"  # financial/legal: require approval + confirmation

# Classify each tool by its risk level
TOOL_RISK = {
    # LOW — read only, fully autonomous
    "search_web":     RiskLevel.LOW,
    "query_database": RiskLevel.LOW,
    "read_file":      RiskLevel.LOW,
    "get_weather":    RiskLevel.LOW,

    # MEDIUM — writes but reversible
    "create_note":    RiskLevel.MEDIUM,
    "save_episode":   RiskLevel.MEDIUM,
    "write_file":     RiskLevel.MEDIUM,

    # HIGH — irreversible or external-facing
    "send_email":     RiskLevel.HIGH,
    "delete_file":    RiskLevel.HIGH,
    "post_to_slack":  RiskLevel.HIGH,
    "create_github_issue": RiskLevel.HIGH,

    # CRITICAL — financial / legal consequences
    "charge_payment": RiskLevel.CRITICAL,
    "deploy_to_prod": RiskLevel.CRITICAL,
    "delete_database": RiskLevel.CRITICAL,
}

# Approval callback — plug in your UI (CLI, web, Slack, etc.)
class ApprovalGate:
    def __init__(self, mode: str = "cli"):
        self.mode = mode   # "cli" | "webhook" | "always_approve" (testing)

    async def request(self, tool: str, args: dict, risk: RiskLevel) -> bool:
        if risk == RiskLevel.LOW:
            return True   # auto-approve low-risk tools

        if self.mode == "always_approve":
            return True   # for testing — never use in production!

        if self.mode == "cli":
            return await self._cli_prompt(tool, args, risk)

    async def _cli_prompt(self, tool: str, args: dict, risk: RiskLevel) -> bool:
        risk_icon = {RiskLevel.MEDIUM:"🟡", RiskLevel.HIGH:"🔴", RiskLevel.CRITICAL:"💀"}
        print(f"""
{risk_icon.get(risk,'⚠️')} APPROVAL REQUIRED [{risk.value.upper()}]
Tool:      {tool}
Arguments: {json.dumps(args, indent=10)}
""")
        # Run blocking input in a thread so we don't block asyncio
        loop = asyncio.get_event_loop()
        answer = await loop.run_in_executor(
            None, lambda: input("Approve? (yes/no): ").strip().lower()
        )
        return answer in ("yes", "y")


# ── Wrap call_tool with approval gate ─────────────────────────
gate = ApprovalGate(mode="cli")

@app.call_tool()
async def call_tool(name: str, arguments: dict):
    risk = TOOL_RISK.get(name, RiskLevel.MEDIUM)

    approved = await gate.request(name, arguments, risk)
    if not approved:
        return [types.TextContent(type="text",
            text=f"⛔ Tool '{name}' was rejected by the user. Stopping.")]

    # Proceed with tool execution as normal
    return await _execute_tool(name, arguments)

Full Research Agent — End-to-End

Here's everything we've learned combined into a single production-ready Research Agent. This agent can autonomously research any topic, remember what it learns, and produce structured reports.

Python — research_server.py (complete production agent server)
"""
Research Agent MCP Server
Tools: web_search, fetch_page, save_to_memory, read_memory, write_report
Features: ReAct agent, persistent memory, metrics, human-in-the-loop
"""
import asyncio, os, json, time, httpx
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.server.models import InitializationOptions
import mcp.types as types

app = Server("research-agent-server")

# In-memory storage (replace with SQLite for persistence)
memory_store: dict = {"findings": [], "reports": {}}

@app.list_tools()
async def list_tools():
    return [
        types.Tool(
            name="web_search",
            description=(
                "Search the web for current information on any topic. "
                "Returns a list of relevant results with titles, snippets, and URLs. "
                "Use this to find recent news, facts, company data, or any information."
            ),
            inputSchema={"type":"object","properties":{
                "query":{"type":"string","description":"Search query (3-10 words)"},
                "num_results":{"type":"integer","default":5,"minimum":1,"maximum":10}
            },"required":["query"]}
        ),
        types.Tool(
            name="save_finding",
            description="Save an important fact or finding to memory for use in the final report.",
            inputSchema={"type":"object","properties":{
                "category":{"type":"string","description":"Category: funding/model/team/product"},
                "fact":{"type":"string","description":"The fact or finding to remember"},
                "source":{"type":"string","description":"URL or source of the fact"}
            },"required":["category","fact"]}
        ),
        types.Tool(
            name="get_findings",
            description="Retrieve all saved findings to review what's been collected so far.",
            inputSchema={"type":"object","properties":{
                "category":{"type":"string","description":"Filter by category (optional)"}
            }}
        ),
        types.Tool(
            name="write_report",
            description=(
                "Write the final research report using all collected findings. "
                "Call this ONLY when you have gathered enough information to write a complete report."
            ),
            inputSchema={"type":"object","properties":{
                "title":{"type":"string"},
                "content":{"type":"string","description":"Full markdown report content"}
            },"required":["title","content"]}
        ),
    ]

@app.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "web_search":
        # Use DuckDuckGo instant answer API (free, no key needed)
        query  = arguments["query"]
        async with httpx.AsyncClient(timeout=10) as c:
            r = await c.get(
                "https://api.duckduckgo.com/",
                params={"q":query,"format":"json","no_html":"1"}
            )
        data   = r.json()
        topics = data.get("RelatedTopics", [])[:arguments.get("num_results",5)]
        results = [t.get("Text","") for t in topics if isinstance(t,dict)]
        text = f"Search: '{query}'\n\n" + "\n\n".join(f"• {r}" for r in results if r) or "No results."
        return [types.TextContent(type="text", text=text)]

    elif name == "save_finding":
        memory_store["findings"].append(arguments)
        return [types.TextContent(type="text",
            text=f"✓ Saved finding [{arguments['category']}]: {arguments['fact'][:80]}")]

    elif name == "get_findings":
        findings = memory_store["findings"]
        cat = arguments.get("category")
        if cat: findings = [f for f in findings if f.get("category") == cat]
        text = f"{len(findings)} findings:\n\n" + \
            "\n".join(f"[{f['category']}] {f['fact']}" for f in findings)
        return [types.TextContent(type="text", text=text)]

    elif name == "write_report":
        title = arguments["title"]
        content = arguments["content"]
        memory_store["reports"][title] = content
        with open(f"{title.replace(' ','_')}.md", "w") as fh:
            fh.write(f"# {title}\n\n{content}")
        return [types.TextContent(type="text",
            text=f"✅ Report saved: {title}.md ({len(content)} chars)")]

    raise types.McpError(types.ErrorCode.METHOD_NOT_FOUND, name)

async def main():
    async with stdio_server() as (r, w):
        await app.run(r, w, InitializationOptions(
            server_name="research-agent-server", server_version="1.0.0"))

if __name__ == "__main__":
    asyncio.run(main())

Publishing to the MCP Registry

Once your server is stable and documented, publish it to the official MCP Server Directory — the community hub where developers find reusable MCP servers. Your server becomes a building block for the entire MCP ecosystem.

1
Polish your README.md

Write a clear README: what the server does, what tools it exposes, how to install and configure it (especially env vars), and a quick start example. Include screenshots of it working in Claude Desktop.

2
Add a proper pyproject.toml or package.json

Make your server installable via pip install your-server or npx your-server. Add proper metadata: name, version, description, author, license.

3

Section 09

Production Readiness Checklist — 25 Points

The definitive checklist. A server that passes all 25 points is production-ready, publishable, and maintainable.

Functionality (8 points)

  • All tools have precise descriptions that tell the LLM exactly when to call them
  • All tool schemas have description fields on every parameter
  • Tools return structured, readable text — not raw JSON blobs or HTML
  • Resources are listed and readable via list_resources and read_resource
  • Prompt templates (if any) work correctly with all argument combinations
  • The initialize handshake completes and correct capabilities are declared
  • Unknown tool names return McpError.METHOD_NOT_FOUND, not a crash
  • All tools run correctly when tested in MCP Inspector

Security (7 points)

  • Authentication middleware rejects unauthenticated requests (API key or OAuth)
  • All string inputs are length-limited and HTML-stripped
  • File paths are checked for traversal attacks (Path.resolve() inside base)
  • SQL queries use parameterized placeholders, never string concatenation
  • External content is sanitized for prompt injection before returning to LLM
  • All secrets are loaded from environment variables, never hardcoded
  • Error messages don't leak internal stack traces or file paths

Reliability (5 points)

  • Every tool handler is wrapped in try/except — no unhandled exceptions
  • Every HTTP call has a timeout (no fire-and-forget awaits)
  • Rate limiting is in place for all tools that call external APIs
  • Integration tests cover: happy path, error cases, edge cases, injection attempts
  • /health endpoint returns 200 OK and is passing Docker HEALTHCHECK

Operations (5 points)

  • Dockerfile is present, builds without error, runs as non-root user
  • Structured logging is in place — every tool call logged with timing
  • Prometheus /metrics endpoint is exposed and scraping works
  • README clearly documents all env vars, installation, and tools
  • requirements.txt pins all dependencies to exact versions
