Integrating a Real API

We'll replace the mocked weather data from Part 2 with real live calls to OpenWeatherMap API (free tier — 1000 calls/day). This teaches you the universal pattern for any REST API integration in MCP.

🔑 Get API Key

Register free at openweathermap.org. Your key arrives by email within minutes. Never hardcode it — use environment variables.

📦 Install httpx

uv add httpx — modern async HTTP client for Python. Works perfectly with async/await and FastMCP's architecture.

🔁 Retry Logic

APIs fail. Networks drop. Always add timeout + retry logic so a momentary hiccup doesn't crash your tool call.

The Real API Integration Pattern

Every real-API MCP tool follows the same 5-step structure. Learn this once — it applies to GitHub, Slack, Stripe, any REST API:

1
Load credentials from environment variables

Never put API keys in your code. Use os.environ.get("API_KEY") or a .env file with python-dotenv.

2
Validate inputs before calling the API

Catch bad arguments early with Pydantic — before spending an API call on something that will fail.

3
Make the async HTTP call with timeout

Use httpx.AsyncClient with a timeout (e.g. 10s). Never await an HTTP call without a timeout — it can hang forever.

4
Handle API-specific error responses

Check HTTP status codes. Map them to meaningful error messages. 401 = bad key, 404 = city not found, 429 = rate limited.

5
Format and return the result as TextContent

Extract only the relevant fields from the API response. Return clean, formatted text — not raw JSON blobs.

Python — Real API tool with FastMCP (full error handling)
import os, httpx, asyncio
from fastmcp import FastMCP

mcp = FastMCP("health-weather-server")

# ── Step 1: Load credential from environment ─────────────────
OWM_API_KEY = os.environ.get("OPENWEATHER_API_KEY")

# ── Step 2: Define constants ──────────────────────────────────
OWM_BASE_URL = "https://api.openweathermap.org/data/2.5/weather"
TIMEOUT_SECS = 10
MAX_RETRIES  = 2

# FastMCP: @mcp.tool() + async def + return plain string ──────
@mcp.tool()
async def get_weather(city: str, units: str = "metric") -> str:
    """
    Get live weather for a city from OpenWeatherMap.
    units: 'metric' (°C) or 'imperial' (°F). Use when user asks about weather.
    """
    # Validate API key exists
    if not OWM_API_KEY:
        return "❌ OPENWEATHER_API_KEY env var not set. Add it to your .env file."

    if not city.strip():
        return "❌ City name cannot be empty."

    # ── Step 3: Make the API call with retry ─────────────────────
    params = {"q": city, "appid": OWM_API_KEY, "units": units}

    for attempt in range(MAX_RETRIES + 1):
        try:
            async with httpx.AsyncClient(timeout=TIMEOUT_SECS) as client:
                resp = await client.get(OWM_BASE_URL, params=params)

            # ── Step 4: Handle HTTP error codes ──────────────────────
            if resp.status_code == 401:
                return "❌ Invalid API key. Check OPENWEATHER_API_KEY."
            elif resp.status_code == 404:
                return f"❌ City '{city}' not found. Check spelling or try a larger city."
            elif resp.status_code == 429:
                return "❌ API rate limit hit. You have 1000 free calls/day."

            resp.raise_for_status()
            data = resp.json()
            break

        except httpx.TimeoutException:
            if attempt == MAX_RETRIES:
                return "❌ Weather API timed out after 3 attempts. Try again later."
            await asyncio.sleep(1.5 ** attempt)   # exponential backoff

        except httpx.HTTPStatusError as e:
            return f"❌ API error {e.response.status_code}: {e.response.text[:200]}"

    # ── Step 5: Format and return — plain string, no TextContent wrapper
    unit_symbol = "°C" if units == "metric" else "°F"
    return f"""🌤️  Live Weather — {data['name']}, {data['sys']['country']}
   Temperature  : {data['main']['temp']}{unit_symbol}
   Feels Like   : {data['main']['feels_like']}{unit_symbol}
   Condition    : {data['weather'][0]['description'].title()}
   Humidity     : {data['main']['humidity']}%
   Wind Speed   : {data['wind']['speed']} m/s
   Visibility   : {data.get('visibility', 'N/A')} m"""

if __name__ == "__main__":
    mcp.run()
💡 Environment Variables — The Right Way

Create a .env file in your project root: OPENWEATHER_API_KEY=your_key_here. Run uv add python-dotenv and add from dotenv import load_dotenv; load_dotenv() at the top of main.py. Never commit .env to git — add it to .gitignore.

Building a SQLite Database MCP Server

A database MCP server is one of the most powerful and commonly needed servers. It lets Claude query, analyze, and explain data from any SQLite database — instantly turning your data into a conversational interface.

Imagine asking Claude: "Show me the top 5 customers by revenue this month" — and it actually queries your real database and returns the live answer. That's what this server enables.

// THE POWER OF A DB MCP SERVER
Diagram 3.2 — SQLite MCP Server Internal Architecture
The DB server has 3 layers: Tools (actions Claude takes), Safety Layer (prevent SQL injection & dangerous queries), and SQLite Engine (async queries). Resources expose schema context so Claude can write correct SQL.

Full SQLite Server Implementation

Python — db_server.py (FastMCP SQLite server)
import aiosqlite, re
from fastmcp import FastMCP

DB_PATH = "database.db"
mcp = FastMCP("sqlite-mcp-server")

# ── SAFETY: block dangerous SQL patterns ────────────────────
BLOCKED_PATTERNS = [
    r'DROP', r'DELETE', r'TRUNCATE',
    r'ALTER',  r'CREATE',  r'EXEC',
    r'ATTACH', r'DETACH',  r'PRAGMA',
]

def is_safe_query(sql: str) -> tuple[bool, str]:
    sql_upper = sql.upper()
    for pattern in BLOCKED_PATTERNS:
        if re.search(pattern, sql_upper):
            keyword = pattern.replace(r'', '')
            return False, f"Blocked keyword: {keyword}"
    if not sql_upper.strip().startswith("SELECT"):
        return False, "Only SELECT queries allowed via query_database"
    return True, ""

# ── TOOL: query_database ─────────────────────────────────────
@mcp.tool()
async def query_database(sql: str, limit: int = 50) -> str:
    """Run a SELECT SQL query on the database. Returns formatted table results. Max 100 rows."""
    limit = min(limit, 100)   # cap at 100 rows

    safe, reason = is_safe_query(sql)
    if not safe:
        return f"❌ Query blocked: {reason}"

    if "LIMIT" not in sql.upper():
        sql += f" LIMIT {limit}"

    try:
        async with aiosqlite.connect(DB_PATH) as db:
            db.row_factory = aiosqlite.Row
            async with db.execute(sql) as cursor:
                rows = await cursor.fetchall()
                cols = [d[0] for d in cursor.description] if cursor.description else []

        if not rows:
            return "✓ Query ran, 0 rows returned."

        header = " | ".join(cols)
        sep    = "-+-".join(["-" * len(c) for c in cols])
        data_rows = [" | ".join(str(r[c]) for c in cols) for r in rows]
        table = f"{header}
{sep}
" + "
".join(data_rows)
        return f"✓ {len(rows)} row(s) returned:

{table}"

    except aiosqlite.OperationalError as e:
        return f"❌ SQL error: {e}"


# ── TOOL: list_tables ────────────────────────────────────────
@mcp.tool()
async def list_tables() -> str:
    """List all tables in the SQLite database."""
    async with aiosqlite.connect(DB_PATH) as db:
        async with db.execute(
            "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"
        ) as cur:
            tables = [r[0] async for r in cur]
    return "📋 Tables in database:
" + "
".join(f"  • {t}" for t in tables)


# ── TOOL: describe_table ─────────────────────────────────────
@mcp.tool()
async def describe_table(table_name: str) -> str:
    """Show schema for a table: column names, types, and constraints."""
    async with aiosqlite.connect(DB_PATH) as db:
        async with db.execute(f"PRAGMA table_info({table_name})") as cur:
            cols = [r async for r in cur]
    if not cols:
        return f"❌ Table '{table_name}' not found."
    lines = [f"📐 Schema for '{table_name}':
"]
    for c in cols:
        pk = " 🔑 PRIMARY KEY" if c[5] else ""
        nn = " NOT NULL" if c[3] else ""
        df = f" DEFAULT {c[4]}" if c[4] else ""
        lines.append(f"  {c[1]:20} {c[2]:12}{nn}{df}{pk}")
    return "
".join(lines)


# ── RESOURCE: full schema ────────────────────────────────────
@mcp.resource("resource://db/schema")
async def db_schema() -> str:
    """Full database schema — all table CREATE statements."""
    async with aiosqlite.connect(DB_PATH) as db:
        async with db.execute(
            "SELECT sql FROM sqlite_master WHERE type='table'") as cur:
            schemas = [r[0] async for r in cur if r[0]]
    return "-- DATABASE SCHEMA

" + "

".join(schemas)

if __name__ == "__main__":
    mcp.run()
⚠️ SQL Injection — Critical Security Rule

Never use f-strings or string concatenation to build SQL with user-supplied values. Always use parameterized queries: db.execute("SELECT * FROM users WHERE id = ?", (user_id,)). The ? placeholder is automatically escaped by SQLite. This prevents SQL injection attacks.

✅ Install aiosqlite

Run uv add aiosqlite — this is an async wrapper around Python's built-in sqlite3 module. It lets you run DB queries without blocking the event loop. FastMCP supports async def tools natively, so aiosqlite integrates perfectly.

Prompt Templates

Prompts are reusable instruction templates with variables. Think of them as "slash commands" for your MCP server — the user activates a prompt and the AI is immediately set up with the right context and instructions for a specific task.

In FastMCP, prompts use a single @mcp.prompt() decorator — similar to @mcp.tool(). The function name becomes the prompt name, the docstring its description, and arguments come from Python parameters. Return a string (becomes a user message) or a list of message dicts for multi-turn templates.

Python — Prompt templates with FastMCP @mcp.prompt()
from fastmcp import FastMCP

mcp = FastMCP("health-weather-server")

# ── @mcp.prompt() — one decorator replaces list_prompts + get_prompt ─
@mcp.prompt()
def analyze_table(table_name: str, focus: str = "general insights") -> str:
    """Analyze a database table: inspect structure, sample rows, and suggest insights."""
    # Return a string → FastMCP wraps it as a user message automatically
    return f"""Please analyze the database table '{table_name}' with a focus on: {focus}.

Steps:
1. Use describe_table(table_name="{table_name}") to see the schema
2. Use query_database(sql="SELECT * FROM {table_name} LIMIT 10") to see sample data
3. Use query_database(sql="SELECT COUNT(*) FROM {table_name}") to see total size
4. Report: column descriptions, data patterns, key statistics, and actionable {focus} insights."""


@mcp.prompt()
def weather_report(city: str, style: str = "detailed") -> str:
    """Generate a full weather report with forecast advice for a city.
    style: 'brief' | 'detailed' | 'casual'"""
    return f"""Fetch the current weather for '{city}' using the get_weather tool, then write
a {style} weather report. Include: temperature, what to wear, activity suggestions,
and any weather warnings. Style: {style}."""
📚 How Prompts Work in Practice

In Claude Desktop, prompts appear as a "/" slash command in the chat interface. The user types /analyze-table, fills in the arguments in the UI, and Claude immediately has a structured instruction set ready — including which tools to call and in what order. It's a productivity multiplier for repeated workflows.

Claude Desktop Multi-Server Config

You can connect Claude Desktop to multiple MCP servers simultaneously. Each one runs as a separate subprocess. Claude sees all their tools, resources, and prompts merged into one unified view.

JSON — claude_desktop_config.json (multi-server setup)
{
  "mcpServers": {

    // ── Server 1: Our health-weather server (uv — no venv path needed)
    "health-weather": {
      "command": "uv",
      "args": ["run", "python", "main.py"],
      "cwd": "/Users/you/mcp-health-server",
      "env": {
        "OPENWEATHER_API_KEY": "your_api_key_here"
                                     // env vars passed to the server process
      }
    },

    // ── Server 2: Our SQLite database server ─────────────
    "my-database": {
      "command": "uv",
      "args": ["run", "python", "db_server.py"],
      "cwd": "/Users/you/mcp-db-server",
      "env": {
        "DB_PATH": "/Users/you/data/myapp.db"
      }
    },

    // ── Server 3: Community filesystem server ────────────
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/you/Documents"     // restrict to this directory only
      ]
    }
  }
}

Server-Side Logging & Sampling

Structured Logging

In production, you need to know what your server is doing. MCP has a built-in logging system — your server sends log messages to the Client via MCP notifications, which Claude Desktop can display.

Python — Structured logging with FastMCP
import logging, json, time
from datetime import datetime, UTC
from fastmcp import FastMCP
from functools import wraps

mcp = FastMCP("health-weather-server")

# Set up Python's standard logging to write structured JSON logs
logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s %(levelname)s %(name)s: %(message)s'
)
logger = logging.getLogger("mcp-server")

# Structured log helper — writes JSON for easy parsing by log aggregators
def log_tool_call(tool: str, duration_ms: float, success: bool):
    logger.info(json.dumps({
        "event":   "tool_call",
        "tool":    tool,
        "ms":      round(duration_ms, 2),
        "success": success,
        "ts":      datetime.now(UTC).isoformat(),
    }))

# In FastMCP, wrap individual tool functions instead of a central call_tool handler
@mcp.tool()
async def get_weather(city: str, units: str = "metric") -> str:
    """Get live weather for a city."""
    start = time.monotonic()
    success = True
    try:
        result = await _fetch_weather(city, units)
        return result
    except Exception:
        success = False; raise
    finally:
        log_tool_call("get_weather", (time.monotonic()-start)*1000, success)

# FastMCP also supports a Context object for sending MCP log notifications
from fastmcp import Context

@mcp.tool()
async def query_database(sql: str, ctx: Context) -> str:
    """Run a SELECT query. Context parameter gives access to MCP notifications."""
    # ctx.info() sends a log notification to Claude Desktop
    await ctx.info(f"Executing query: {sql[:80]}")
    try:
        result = await _run_db_query(sql)
        await ctx.info("Query completed successfully")
        return result
    except Exception as e:
        await ctx.warning(f"Query failed: {e}")
        return f"❌ Error: {e}"
# ctx levels: ctx.debug() | ctx.info() | ctx.warning() | ctx.error()

What is Sampling? (Advanced)

Sampling is one of MCP's most powerful — and least-known — features. It allows the Server to ask the Host's LLM to generate text on its behalf. This enables servers to do AI-powered reasoning internally, without needing their own LLM API key.

🧠 Sampling — Server asks LLM to think for it

Example: your database server calls a complex query, gets 500 rows of raw data, and then uses sampling to ask Claude to summarize it into a natural-language insight — all before returning the tool result. The server uses the Host's LLM as a "reasoning engine" internally. This is how you build truly intelligent MCP servers.

Python — Sampling request (server asks LLM to think)
from mcp.types import CreateMessageRequestParams, SamplingMessage

# Inside a tool handler — server requests LLM completion from the Host
async def _smart_query_summary(raw_data: str, ctx) -> str:
    """Ask the Host's LLM to summarize raw query results."""
    result = await ctx.request_sampling(
        CreateMessageRequestParams(
            messages=[
                SamplingMessage(
                    role="user",
                    content=types.TextContent(
                        type="text",
                        text=f"""
Summarize this database query result in 2-3 bullet points.
Focus on key trends and anomalies. Be concise.

Data:
{raw_data}
"""
                    )
                )
            ],
            maxTokens=300,
        )
    )
    return result.content.text

Switching to HTTP + SSE Transport

For production deployment, we switch from stdio (local subprocess) to HTTP + SSE transport. This lets your server run anywhere on the internet and serve multiple clients simultaneously.

Diagram 3.3 — HTTP+SSE Two-Endpoint Architecture
Two HTTP endpoints: GET /sse opens a persistent stream (for Server→Client pushes). POST /messages receives tool calls (Client→Server). The session_id links them together.
Python — HTTP+SSE server using FastMCP built-in transport
# Install: uv add fastmcp uvicorn
# FastMCP has built-in SSE transport — no Starlette boilerplate needed

# ─── http_server.py ──────────────────────────────────────────
from fastmcp import FastMCP

mcp = FastMCP("health-weather-server")

# ... your @mcp.tool(), @mcp.resource(), @mcp.prompt() definitions ...

# Only the entry point changes — everything else is identical to stdio mode
if __name__ == "__main__":
    mcp.run(
        transport="sse",       # switch from default stdio to HTTP+SSE
        host="0.0.0.0",        # listen on all interfaces (required for Docker)
        port=8000,             # port to expose
    )
# FastMCP wires up /sse and /messages/ endpoints automatically.
# The /health endpoint is also built-in: GET /health → {"status": "ok"}
TERMINAL — Test locally before deploying

Dockerize Your MCP Server

Docker packages your server and all its dependencies into a portable container. The same container runs identically on your laptop, on Railway, on AWS — everywhere. No "but it works on my machine" problems.

Dockerfile — production-ready MCP server image
# ── Base image ────────────────────────────────────────────────
FROM python:3.12-slim

WORKDIR /app

# Install curl (for health check) and uv
RUN apt-get update && apt-get install -y curl \
    && rm -rf /var/lib/apt/lists/* \
    && pip install uv               # uv manages the venv inside the container

# ── Copy lockfile + project config FIRST for Docker layer caching ─
# If only code changes, this layer is cached → faster rebuilds
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev    # install exact locked versions, skip dev deps

# ── Copy application code ─────────────────────────────────────
COPY . .

# ── Security: don't run as root ───────────────────────────────
RUN useradd -m appuser && chown -R appuser /app
USER appuser

# ── Runtime configuration ─────────────────────────────────────
EXPOSE 8000

# Health check — FastMCP exposes /health automatically
HEALTHCHECK --interval=30s --timeout=10s --start-period=5s --retries=3 \
    CMD curl -f http://localhost:8000/health || exit 1

# Start with uv run — uses the .venv created by uv sync above
CMD ["uv", "run", "python", "http_server.py"]
YAML — docker-compose.yml (local testing)
version: '3.9'

services:
  mcp-server:
    build: .                            # build from Dockerfile in current dir
    ports:
      - "8000:8000"                     # expose port 8000
    environment:
      - OPENWEATHER_API_KEY=${OPENWEATHER_API_KEY}  # from your .env file
      - DB_PATH=/data/database.db
    volumes:
      - ./data:/data                   # mount local ./data folder into container
    restart: unless-stopped           # auto-restart on crash
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
TERMINAL — Build and test Docker locally
$ docker build -t my-mcp-server .
Successfully built a1b2c3d4e5f6
$ docker compose up
mcp-server | INFO: FastMCP SSE transport running on http://0.0.0.0:8000
$ curl http://localhost:8000/health
{"status": "ok"}
✓ Container is healthy and ready to deploy
